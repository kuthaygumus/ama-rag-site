## Common questions

<FAQ q="Do we process the whole corpus again on every change?">
No. `ingest` processes only the edition you give it. Texts that didn't change come from the cache. Real systems use a finer way: delete and rewrite only the chunks of the document that changed. We didn't measure this in this repo ([Performance and cost](/en/uretim/performans-maliyet/)).
</FAQ>

<FAQ q="What about documents with no edition number?">
The same idea works with other fields: `docId` and an update date. When a document changes, you delete the records of that `docId` and write the new ones. The search always sees the latest record.
</FAQ>

<FAQ q="What would this mean for a fine-tuned model?">
It means training again with the new data, testing again and deploying again. Making the model forget the old number is a separate job. Here we added a folder and ran one command ([RAG or fine-tuning?](/en/neden-rag/rag-mi-fine-tune-mu/)).
</FAQ>

<FAQ q="What if a user asks about their leave in 2025?">
With the "latest" filter, the 2025 number never reaches the prompt. You can read the year from the question and put it in the filter (question analysis). But this repo doesn't do that. Keeping the old edition helps only with a step like that.
</FAQ>

<Takeaway>The model didn't change. The documents changed, and the answer followed them.</Takeaway>
