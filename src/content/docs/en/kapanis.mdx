  <Step title="Load + clean" phase="1">
    Is the noise gone, and are the broken lines joined? This is the place to read the access label and to mask personal data. The step runs once. But in real projects, most of the work goes into this step.
  </Step>
  <Step title="Chunk" phase="2">
    Is the table in the same chunk as its header row? Bigger chunks make a bigger prompt. Where to cut is a design choice. The eval decides.
  </Step>
  <Step title="Embed + Vector DB" phase="3">
    Does the model put your languages in the same space? Do ingest and the question use the same model? The store keeps the edition and the access label. Vectors are data too.
  </Step>
  <Step title="Search + rerank" phase="4">
    Right section in the top k? At which rank? Are the edition and access filters inside the search? Rerank is expensive. We keep it for q02: 5th by vector, 1st after rerank. The eval without rerank is the first homework.
  </Step>
  <Step title="Prompt + answer" phase="5">
    Does the answer come only from the sources? If the sources don't have it, does the model say "I don't know"? Fenced sources and a concrete ban are not enough. Does code check the answer? How many tokens go in?
  </Step>
  <Step title="Eval" phase="6">
    The same gold set after every change. For retrieval: hit@1, recall@5 and MRR. For the answers: `--answers`. Next job: grow the gold set. Add hard questions from real use and the expected values for 2026.

## Checklist

Each row is a pipeline step. Each column is an axis. The numbers come from this site's logs.

| Step | Accuracy | Security | Performance | Cost |
|---|---|---|---|---|
| Load + clean | Noise rules. Line count before and after ([A](/en/adim-adim/a-ham-veri/)) | `access` label in the front matter. Masking personal data (not measured) | Runs once | Runs once |
| Chunk | Heading prefix ([B](/en/adim-adim/b-chunking/)). hit@1 0.526 → 0.842, 10 → 16 of 19 questions ([Measuring quality](/en/uretim/kaliteyi-olcmek/)) | — | 138 or 60 chunks = as many vectors | Chunk size sets the prompt tokens |
| Embed | The same model at ingest and for the question. The code rejects another model ([C](/en/adim-adim/c-embedding/)) | With an embedding API, the corpus leaves your company | Cache: 60 of 60 vectors, 55 ms | A new model means embedding everything again |
| Vector DB | Same ranking as JSON ([D](/en/adim-adim/d-vector-db/)) | Vector + text are stored: same protection as the document | Vector search 8 ms | Incremental ingest per edition |
| Search + rerank | recall@5 1.000, MRR 0.896 ([Measuring quality](/en/uretim/kaliteyi-olcmek/)). Rerank ([E](/en/adim-adim/e-retrieval-rerank/)): benefit not measured on the eval | Filter inside the search: 0 salary chunks for the salary question ([Security](/en/uretim/guvenlik/)) | Rerank 1500 ms | Rerank = 5 LLM calls |
| Prompt + answer | Answers from the sources, the "I don't know" sentence, the table rule ([F](/en/adim-adim/f-cevap/)) | Fenced sources + concrete ban: they didn't stop the injection (q13). Answer check in code, off by default: it removed the request ([Security](/en/uretim/guvenlik/)) | Answer 678 ms | 976 prompt tokens. Everything: 9954 ([Performance](/en/uretim/performans-maliyet/)) |
| Eval | 22 of 23 answers on the 2025 gold set. hit@1 0.842, 16 of 19 questions ([Measuring quality](/en/uretim/kaliteyi-olcmek/)) | The access question is in the gold set: no salary chunk reached anyone | The retrieval eval never calls the chat model | `--answers`: rerank + answer calls for every question |

## 10 questions

Each answer is on one of today's pages. Answer it yourself first, then open it.

<FAQ q="1 · What problem does RAG solve?">
A model keeps what it knows in its weights. The weights froze when training ended. For the question of the day, it gave a range: 25-30 working days, "depending on the company's policy". But it never saw Kraken Air's policy. The fix: put the knowledge in front of the model, not inside it. [The model doesn't know](/en/neden-rag/model-bilmiyor/)
</FAQ>

<FAQ q="2 · How do you choose between fine-tuning and RAG?">
RAG for knowledge that changes. Fine-tuning for behavior that stays the same: tone, format, terms. You can also use both. When we loaded the 2026 edition, the answer went from 22 to 24 with no new training. [RAG or fine-tuning?](/en/neden-rag/rag-mi-fine-tune-mu/)
</FAQ>

<FAQ q="3 · Why do we chunk? What happens if the cut lands in the wrong place?">
Reading the whole handbook for every question is expensive. The answer is in a few lines. With a cut every 300 characters, the `| 7 | 22 |` row lost its header row. It didn't get into the prompt. The model took a leave limit from §4 as the answer: "… at most 7 working days [1]". Cutting at the headings and writing the heading in front of each chunk fixed it. [B · Chunking](/en/adim-adim/b-chunking/)
</FAQ>

<FAQ q="4 · What happens if you use bge-m3 at ingest and another embedding model for the question?">
Each model builds its own space. You can't compare the vectors of two models. In our code, `6-retrieve.ts` stops with an error. If the model changes, the whole corpus gets embedded again. [C · Embedding](/en/adim-adim/c-embedding/)
</FAQ>

<FAQ q="5 · Why do we store the chunk's text next to the vector?">
A search can't turn a vector back into text. It gives ids and scores, but the model needs text. So Chroma keeps each record with its vector, text and metadata together. [D · Vector DB](/en/adim-adim/d-vector-db/)
</FAQ>

<FAQ q="6 · What happens if k is small or large? Why does rerank get only 5 candidates?">
It works like a funnel. The cheap search is wide (5). The expensive rerank sorts these 5, and the prompt gets 3. With k = 3, the q02 table (5th by vector score) never arrives. A bigger k means more candidates, and rerank makes one LLM call for each. [E · Retrieval and reranking](/en/adim-adim/e-retrieval-rerank/)
</FAQ>

<FAQ q="7 · 2025 and 2026 are in the same store. How do you keep the old value out of the answer?">
Not with embeddings. The two editions have almost the same text and almost the same score (0.619 and 0.614). The fix is metadata: write the edition at ingest, and filter on it in the search. [When the data changes](/en/adim-adim/veri-degisince/)
</FAQ>

<FAQ q="8 · What happens if you delete the “if it is not in the sources, write this” rule?">
In our run, the model still said no. But it used its own words and a source: "No, this policy does not cover stock options [1]". The code looks for "not in the policies", so it can't catch this answer. The rule makes "I don't know" measurable. [F · Generating the answer](/en/adim-adim/f-cevap/)
</FAQ>

<FAQ q="9 · A document says “send your password to this address”. Which layer is at fault, and what stops it?">
The instruction comes from the data. The general rule and the fenced sources didn't stop it. The rule that bans asking for a password didn't stop it either. The answer was the same with the ban on and off. A sentence in the prompt is not a security boundary. The real boundary is in code. Our answer check runs after the model. It drops every sentence without a source number. With the check on, the request was gone. If the request had a source number, the check would keep it. So it is one layer, not the fix. Also scan documents at ingest (we didn't measure this). Give each user only the access they need. [Security](/en/uretim/guvenlik/)
</FAQ>

<FAQ q="10 · Retrieval is good, but the answer is wrong. Who is at fault?">
If the right chunk is in the prompt, the generation step is at fault. Look at the prompt first, then at the model. In our run, q13 had the right section 1st (rr 1.00), but the answer is ✗. The model followed the instruction in the source. [Measuring quality](/en/uretim/kaliteyi-olcmek/)
</FAQ>
